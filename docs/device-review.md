# 设备端稳定性审查

审查日期：2026-11-11。范围为 ARM Linux 入口、Wi-Fi/发现/API、配置存储、
语音与音频子进程、Live2D/GIF/照片/字体和 DRM/EGL 生命周期，以及部署依赖。
Windows 后端与云账户不属于本轮设备端审查范围；共用代码补做 Windows Release 构建。

## 已修复的问题

| 优先级 | 触发条件与影响 | 修复 |
| --- | --- | --- |
| P1 | Wi-Fi 入网重试沿用旧计时，第二次尝试被立即判超时 | 每轮刷新计时，留出接口初始化、锁等待及 DHCP 时间 |
| P1 | AP/client/off 并发，旧停止脚本拆掉新热点；后台进程继承锁 | 共享锁、启动守护进程前关闭锁描述符、锁内核对目标模式 |
| P1 | DHCP 客户端残留抢走 AP 网关，热点可见但取址/配网页失败 | 按配置/接口核实进程身份后停止；保留已有 AP 关联，修复网关及 DHCP/DNS |
| P1 | hostapd 短暂启动失败被当作驱动崩溃，触发整机重启 | 增加启动宽限，重试 Wi-Fi，不再自动重启系统 |
| P1 | 自动选到信道 11 后，热点可见但测试网卡无法完成关联；相同设备切至 6 后恢复 | 停用 AP 自动换信道，固定已验证的 2.4GHz 信道 6，保留附近 SSID 扫描 |
| P1 | aplay/ASR/ffmpeg 不退出或持续输出，退出卡住、解码线程悬空 | 非阻塞管道、有界读写、TERM/KILL/回收、有界解码与队列、析构 join；D 状态保留 PID 抑制无限重建 |
| P1 | 损坏/超大 GIF、图片、WAV、模型导致过量分配或空指针访问 | 下载/文件/像素/帧数/音频时长限额；GIF 解码前检查结构与总像素预算；验证模型加载和内存分配 |
| P1 | 翻页超时后释放仍被 DRM 扫描输出的缓冲区，事件指针失效 | 保留待完成翻页及缓冲区，收到完成事件才释放旧缓冲；退出先停止扫描 |
| P1 | GL 上下文/Live2D Framework 先销毁，随后资源析构访问失效对象 | 调整作用域与销毁顺序，资源先释放，再关闭 Framework/GL |
| P2 | 配网页启动失败不重试；SSID/密码修剪破坏合法空格；配置注入 | 同步 bind、失败重试、请求限额/超时、HTML 转义、按字节验证凭据、SSID hex 编码 |
| P2 | 断电/部分写入破坏身份与 Wi-Fi 配置，敏感配置权限过宽 | 同目录临时文件、0600、fsync 与原子 rename，保存失败不切网；启动时收紧旧版本文件权限，不重写凭据 |
| P2 | 配置类型/整数溢出、负动作序号触发异常行为 | 严格校验整数类型、范围和字段类型 |
| P2 | 发现到未配对 PC 覆盖目标、旧地址响应污染新状态 | 优先新鲜配对广播，目标版本检查，失效 token 持久清除，待执行配网命令保留至消费 |
| P2 | 菜单请求缺少配对令牌、媒体下载无大小限制 | 补鉴权头，流式限制下载大小，原子保存 |
| P2 | 图片请求失败反复重试、字体/着色器失败泄漏、GIF 换尺寸花屏 | 失败冷却、临时加载成功后交换、失败清理、换尺寸重建纹理 |

热点密码不轮换是既有设计：首次生成后写入 `~/.dutyon/device.json`。
本轮保留此行为，避免已保存热点的手机因密码变化反复认证失败。
日志不输出热点密码、配对码或令牌。

## 验证

- ARM64 Release 交叉构建通过。
- Windows Release 共用代码构建通过；仍有 APIENTRY 宏重定义和 LIBCMT 链接警告。
- 回归测试程序在电脑交叉编译、上传 OrangePi 后执行通过；退出后无模拟音频子进程遗留。
  Wi-Fi/Test shell 语法与两条 PowerShell 部署入口解析通过。
- 最终二进制及五个脚本已备份旧版本后部署。二进制本地/设备 SHA-256 一致
  （`e7c021243b3ad0df695f66a3491fa7a9602410a7d6a03bcd8bf19da994810e6c`）。
- 真机入网计时记录：首次启动后 65 秒重试，第二轮约 66 秒后回退热点，未删除家庭 Wi-Fi 凭据。
- Ugreen USB 无线网卡连接最终版本 `DutyOn-D8FB`，获得 `192.168.4.195`，
  网关/DNS 为 `192.168.4.1`；绑定无线源地址的配网页 HTTP 200（6424 字节），
  `/generate_204` 返回 302 至 `http://192.168.4.1/`。
- 故障注入：通过 USB 管理连接临时移除 `wlan0` 的 AP 网关，7 秒后检查地址已自动恢复，
  hostapd PID 保持 2383，dnsmasq 从 2391 换至 3036，配网页恢复 HTTP 200。
- `systemctl restart dutyon` 约 2 秒完成，重启前后 Wi-Fi 凭据及设备身份文件校验一致。
- 信道对照测试：使用 Windows `WlanScan` 刷新客户端扫描，信道 11 下仍关联失败，
  切至 6 后连接及 HTTP 立即恢复。测试期间 USB 网卡也曾从 Windows 设备列表中消失，
  用户重新插入后继续验证；不能据此把全部关联故障归因于开发板固件。
- 信道 6 下两次连续断开重连均取得地址并访问配网页；第三次测试因 USB 网卡消失中止，
  该轮未完成。重新插入后，180 秒采样的 19 次 HTTP 请求全部返回 200；
  该短时采样不代替长时间稳定性验证。
- 补测发现旧版 `wifi.json`、`device.json` 为 0644。增加启动权限迁移后，真机两文件
  自动变为 0600，内容 SHA-256 保持一致；回归覆盖保留内容、拒绝符号链接/非普通文件。
  补丁在电脑交叉构建后，设备回归测试再次通过。最终程序重启耗时约 1.9 秒。
- 最终服务重启后，65 秒重试、再约 66 秒回退 AP，正式生成的配置固定信道 6，
  已清除临时诊断用的 hostapd 控制接口。再次执行完整三轮断开重连全部通过，
  每轮均获得 DHCP 地址并返回 HTTP 200，最终探测路径仍返回 302。
  服务保持 active，`NRestarts=0`；二进制和五脚本的本地/设备哈希全部一致。

`device/tests/device_tests.cpp` 覆盖凭据边界、GIF 截断和预算、旧文件权限迁移、私有原子写入、
写入失败保留旧配置、畸形 JSON 配置、有界子进程终止，以及模拟 aplay/ffmpeg
阻塞、静默和连续输出时的退出。音频测试使用临时可执行程序替身，不打开声卡。

Linux 主机有足够内存时可运行：

```sh
sh device/tests/run-device-tests.sh /path/to/nlohmann-json/include
```

低内存开发板建议在电脑使用 ARM64 工具链编译上述测试与
`config/user_config.cpp`、`audio/sound_player.cpp`，再上传运行 `timeout -k 2 30 ./device-tests`。
本轮在运行图形服务的设备上编译测试时发生 SSH/HTTP 无响应；检查可取得的前次启动内核日志
没有定位到 OOM 原因，不能排除日志未落盘，后续改为电脑交叉编译。

## 仍需跟踪

- UWE5622/sprdwl_ng 历史内核日志出现 WCN assert（`rf_marlin.c:1016`）。
  应用修复不能保证驱动恢复，需更多手机、断电与长时间运行验证。
- 手机自动弹窗尚未实测。设备本地 UDP/TCP DNS 均将测试域名解析到 `192.168.4.1`；
  Windows 无线源地址的 UDP 查询超时、TCP 查询被系统拒绝，现有 VPN/TUN 或本机网络策略
  影响尚未排除，设备端 DNS 正常不等于无线客户端的端到端 DNS 已验证。
- 模型/GIF/音频同步下载仍有主线程同步调用，网络慢时可暂停画面与 Wi-Fi 轮询；
  后续应做后台下载和分阶段加载。
- API 状态/指标 JSON 尚未统一施加流式大小上限；错误字段可能丢弃整轮响应。
- DRM 退出会尝试禁用 CRTC，但未恢复先前显示状态，且禁用失败路径仍需专项测试。
- D 状态内核 I/O 无法由用户态 SIGKILL 强制唤醒；当前只保证程序不无限等待或无限创建替代子进程。

## 部署要求

更新必须同时包含二进制及 `wifi-common.sh`、`wifi-ap.sh`、`wifi-client.sh`、
`wifi-off.sh`、`arp-keepalive.sh`。脚本采用 LF 换行，权限 0755。
手动交叉部署与 PC 自动同步入口均已补齐共享脚本的上传。
仅操作设备 `wlan0`，不停止全局网络服务，以保留 USB NCM 管理连接。
升级前备份现有二进制和脚本；不得为测试删掉用户家庭 Wi-Fi 凭据。
