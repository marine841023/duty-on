# TURZX 5.2 寸专属显示屏

## 目标

图灵智显 5.2 寸屏优先使用官方“桌面模式”驱动传输画面，DutyOn 自动在这块屏
显示原生分辨率的不透明、无边框置顶窗口，覆盖桌面背景及任务栏。
专属副屏与独立 Linux 设备直接共用 `TaskPanel::screenLayout` 和
`TaskPanel::renderScreen`，统一角色视口、舞台光、时钟日期、任务牌和提醒边框。
横屏左侧显示角色、右侧显示信息；竖屏按同一规则上下排列。普通桌宠窗口保留
ImGui 面板；专属屏不显示系统监控面板。中文字体随安装器和更新包一并分发。

此方案仍由 Windows 管理显示器；锁屏、安全桌面或其他系统置顶界面可能覆盖
DutyOn，程序退出后恢复普通桌面。它不提供操作系统层面的独占隔离。

## 桌面模式（推荐）

先在官方程序点击“桌面模式”，并安装其配套显示驱动。实测设备会重新枚举为：

- USB：`VID_1A86&PID_AD11`，显示接口为 `MI_00`，另有厂商 HID 接口；
- 驱动名称：`TURZX Display`（UMDF / IddCx 间接显示驱动）；
- 显示器硬件标识：`TUR0000`；
- 本机原生横屏分辨率：`1280×720`，驱动提供 `30Hz` 和 `60Hz` 模式。

DutyOn 按显示器硬件标识识别目标，不依赖容易变化的 `DISPLAY16` 等编号，
也不会占用主显示器。拔出屏幕后自动恢复普通桌宠，重新接入后自动进入专属屏。
屏幕必须处于扩展显示状态；复制显示或将它设为主显示器不适用于此自动模式。

进入专属模式时优先临时选择当前分辨率下最高、不超过 60Hz 的刷新率，不写入
显示设置注册表。退出或切回普通桌宠时，如果当前模式仍与 DutyOn 设置一致，
恢复进入前的方向、分辨率和刷新率。用户自行更改的显示模式不应被覆盖。
强制结束进程时无法执行恢复，必要时可在 Windows 显示设置中调整。

专属模式默认阻止鼠标从其他屏幕进入 TURZX。按住 Ctrl+Alt 可临时进入，
松开后仍可把鼠标移出。副屏拔出、切换到直连模式或退出应用时解除拦截。
专属屏客户区使用系统箭头。
屏幕窗口禁止拖动和边缘吸附，避免露出桌面。托盘右键在鼠标旁弹出 Windows
原生菜单，内容与角色右键菜单一致，支持形象、动作、角色设定、显示、语言、
设备、声音、集成、云端账户、更新、隐藏及退出；隐藏时该项变为“显示”。
打开托盘菜单不会显示桌宠窗口或在副屏展开菜单。原托盘专有操作并入共用菜单：

- “设备 → 无线设备 → 配对设备”：输入配对码或管理无线设备；
- “设备 → 副屏设备 → 副屏模式”：选择“直连模式（USB）”或“Windows 副屏模式”，选择会保存到本机 `secondaryDisplayMode`，重启后沿用；
- “设备 → 副屏设备 → TURZX 桌宠专属屏”：切换整屏输出与普通透明桌宠；
- “设备 → 副屏设备 → 禁止鼠标进入”可切换鼠标拦截，设置会保存在本机。
- “显示 → 移至屏幕正中”：普通桌宠窗口居中；
- “设备 → 屏幕旋转”：立即切换 0° / 90° / 180° / 270° 并保存；
- “隐藏”：专属模式下隐藏角色和面板，但保留不透明背景；
- “退出”：关闭程序并释放显示器，恢复 Windows 桌面。

`DUTYON_TURZX_DESKTOP=0` 可关闭自动专属模式；`DUTYON_TURZX=0` 可关闭下面的
直接 USB 发送后端。未选择过副屏模式时保留自动识别：优先 Windows 专属屏，
未进入专属屏时尝试 USB 直传。手动选择 Windows 副屏模式后停用 USB 发送；
选择直连模式后退出 Windows 专属屏并启用 USB 发送。已进入桌面专属模式时，
不启动直接 USB 图像发送。
菜单切换 DutyOn 的输出通道；屏幕硬件仍需在官方工具中切换到对应模式：
直连使用“普通模式”，Windows 副屏使用“桌面模式”、显示驱动及扩展显示。
两类设备共用的内容模式、相框播放、时钟颜色、亮度、音量和旋转仍在“设备”下。
副屏旋转使用 Windows 桌面驱动的方向设置，90° / 270° 后按原生 720×1280
重新布局；鼠标坐标也由系统同步，不拉伸横屏画面。旋转失败时通知用户且不保存
失败的角度。专属模式退出时恢复进入前的方向、分辨率和刷新率，用户自行修改过
的显示模式不覆盖。独立 Linux 设备继续使用自身的旋转合成，再共用同一套布局。
两端界面统一以短边 480 像素为设计基准，按实际短边等比例计算字号、卡片高度、
图标和间距，并用缩放后的实际字号烘焙字形。720 像素短边使用 1.5 倍字号，
横竖屏切换时重新计算布局。时钟较初始设计放大约 16%～25%，顶部预留高度同步增加。
专属屏右键菜单单独按短边 / 360 缩放，横竖屏字号一致；720 像素短边的菜单正文
为 30 像素，菜单宽度、行高和点击区域同步放大，超长菜单仍可滚动。
日志每 10 秒记录应用渲染帧率；这不是屏幕实际收到的独立帧数，GIF 动画本身
也可能只有较低帧率。显示器刷新率、应用渲染帧率与素材帧率应分别判断。

验收时应检查驱动能切换至屏幕支持的刷新率，应用渲染尺寸与方向一致，
正常退出能恢复进入前的显示模式。0° / 180° 使用 `1280×720`，90° / 270°
使用 `720×1280`；应用渲染统计不能代替物理屏幕帧率测量。托盘交互、热插拔和
不同刷新率仍应在目标设备上回归。

## 直接 USB 模式

官方普通模式中的已适配设备会枚举为 TURZX1.0，并绑定通用 WinUSB。
Windows 绑定通用 WinUSB，设备暴露一个厂商类接口（class `0xFF`）：

- Bulk OUT：`0x01`，最大包长 512 字节；
- Bulk IN：`0x81`，最大包长 512 字节。

此模式未枚举 HID 接口，因此旧版探测器中的 HID 报告和 `AA 55 33`
查询不适用。官方程序通过上述 WinUSB 接口发送画面。

图像帧协议已经通过官方程序源码和 USBPcap 抓包确认，DutyOn 已实现同一协议：

1. 将桌宠帧编码为 `720×1280` RGBA PNG。
2. 生成 500 字节命令头，命令字节为 `0x66`，字节 `2/3` 固定为 `26/109`，
   字节 `8..11` 写入 PNG 长度（大端）。
3. 用 ASCII 密钥/IV `slv3tuzx` 做 DES-CBC + PKCS7 加密；加密后的 504 字节
   放在 512 字节头部前端，字节 `510..511` 为 `A1 1A`。
4. 将 512 字节头和 PNG 内容拼接，通过 Bulk OUT `0x01` 按 512 字节块顺序写入；
   随后从 Bulk IN `0x81` 等待本帧确认包，确认完成后才发送下一帧。设备端点对
   整帧一次性提交会在连续运行后超时，因此不能合并成单次大传输。

抓包中每次图像传输的偏移 `512` 处均出现 PNG 签名 `89 50 4E 47`，传输长度与
官方日志中的 `PushImage` 长度一致。DutyOn 按约 1.2 秒的安全间隔发送帧；端点
超时后会取消并等待异步请求结束、关闭句柄，再重新枚举设备。该通道适合低频
画面，持续动画的速度明显不足，因此当前优先采用官方桌面驱动。

## 诊断

需要分析直连协议时，先确认系统已安装 USBPcap，并从 USBPcap 控制设备列表和当前
设备树读取根集线器、设备地址。设备地址会在重新枚举后变化，不能把端口号或旧地址
写死；抓包时只选择 TURZX 对应的设备，避免把键盘、存储设备等无关流量写入文件。

Windows 构建会生成 `device/build/Release/turzx_probe.exe`。设备接通后运行：

```powershell
.\device\build\Release\turzx_probe.exe
```

工具只枚举已适配的直连设备，打印设备接口、节点状态、WinUSB 端点和 HID
（若设备确实暴露 HID）报告长度。它不会安装驱动、切换模式或写入图像数据。输出结果
可以用于后续 USB 抓包和帧协议实现。

探测器不会写入图像端点。桌面模式的 USB 标识不同，不会出现在该工具的
WinUSB 设备列表中，应通过 Windows 显示设置或 PnP 显示设备检查。

## 实现边界

直接 USB 后端只提交 DutyOn 渲染帧；屏幕拔出、USB 超时或协议校验失败时，
关闭句柄并在下一帧重新枚举，不阻塞桌宠主循环。桌面模式则复用已安装的官方
驱动，不安装或替换自制内核驱动，也不需要继续运行逐帧 PNG 发送程序。
