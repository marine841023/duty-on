# DutyOn v1.3.2 — Hook 状态机修复版

> 下载：[GitHub](https://github.com/marine841023/duty-on/releases/download/v1.3.2/DutyOn-v1.3.2.zip) · [Gitee](https://gitee.com/megrezsoft/dutyo/releases/download/v1.3.2/DutyOn-v1.3.2.zip)（.zip，解压后运行安装器）

1.x 维护版：修复三个 Hook 状态机故障（完整分析见 `docs/fault-records.md`），并同步了与 2.0 交替安装所需的注册表约定。

## 🔧 修复内容

1. **子代理 / 长命令执行期间宠物误睡**
   - 故障：PreToolUse → PostToolUse 之间完全静默（长构建、子代理长任务可达十几分钟），3 分钟超时把"正在干活"误判为空闲，宠物睡着。
   - 修复：pending_tool 记账（PreToolUse 标记、PostToolUse/新提示清除），有工具在执行时超时阈值放宽到 15 分钟。

2. **Notification 类型遗漏**
   - 故障：Trae 官方 5 种通知（idle_prompt / permission_prompt / document_review / ask_user_question / browser_interaction）中后 3 种未识别，Plan 审阅、智能体提问、浏览器等待时宠物不提醒。
   - 修复：全部识别并触发提醒；歧义通知保持可配置。

3. **迟到 / 乱序通知导致提醒永久卡死**
   - 故障：Notification 是异步事件，可能迟于 PostToolUse 送达。迟到的权限确认类通知没有对应的 pending_tool，却把会话置为"待确认"，alert 永不消失。
   - 修复：工具绑定类确认通知到达时若无 pending_tool 则判过期忽略；Notification 分支不再错误清除 pending_tool。

## ✅ 验证

97 个单元测试全过 + 运行实例 9 场景端到端验证（prompt / 工具执行 / 权限确认 / 迟到通知 / UI 流程通知 / 空闲等）。

## 💡 内存占用勘误

1.x 文案曾宣传"内存仅 ~80MB"，该数字只统计了主进程，未计入 WebView2 运行时的浏览器进程群（实测约 400MB）。实测全进程合计约 465MB（工作集）/ 195MB（私有内存）。详见 v2.0.0 发布说明——**v2.0 原生 C++ 单进程版实测仅 ~116MB，真实下降一半以上**。

解压 zip，运行 `DutyOn_1.3.2_x64-setup.exe`。可与 2.0 版互相覆盖安装、共用配置。Windows / macOS / Linux。
